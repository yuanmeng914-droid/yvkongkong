# AI 每日成长分析（AI-2）设计

## 目标

在“成长记录”中提供一次由用户主动发起的当天总结。它只基于该用户选择日期的任务、心情与每日复盘，给出温和的文字反馈，不替用户做决定。

## 用户体验

登录用户在成长记录页保存或填写每日复盘后，可点击“AI 看看今天”。页面显示加载状态，完成后以三段内容呈现：今天的小结、温和的观察、明天的一小步。没有足够当日内容时，页面说明可以先留白，不调用模型。

同一天已有分析时优先读取并展示云端结果。用户可点“重新看看今天”才重新调用模型。未登录用户看见登录提示。

## 数据边界与隐私

- 只读取当前用户、当前选择日期的数据。
- 读取：当天任务统计（不上传任务标题）、当天心情与备注、当天复盘三项文字。
- 不读取 `user_memories`，不建立长期记忆候选，不进入自由聊天。
- 不自动修改任务、心情、复盘、重要日子或记忆。
- 结果由用户可读、可重复生成，并只保存给该用户自己读取。

## 架构

浏览器只发送 `action: "daily_analysis"` 与选定日期。`growth-agent` 根据登录 JWT 在服务端读取 Supabase 表，构造受限摘要并调用既有统一 Model Provider。GLM Provider 仍只负责模型请求与 JSON 解析。Growth Agent 验证模型的三段结果、保存至 `ai_daily_insights`，再返回给前端。

## 数据结构

`public.ai_daily_insights`：每用户每天一条，主键为 `(user_id, insight_date)`。保存 `summary`、`observation`、`tomorrow_suggestion`、不含任务标题的 `source_snapshot`、模型名和时间戳。启用 RLS，用户只能读写自己的行。

## 错误体验

- 未登录：提示先登录。
- 当日没有任务、心情或复盘：提示“今天还不需要总结，也可以晚些再来”。
- 后端返回 `missing_api_key`、`provider_request_failed`、`provider_invalid_response` 或网络错误：显示不泄露上游信息的温和失败提示。

## 明确不在本期范围

- 长期记忆读取与 AI 自动写入记忆。
- 周/月成长报告。
- AI 自由聊天。
- 自动夜间生成、后台定时任务或推送。
