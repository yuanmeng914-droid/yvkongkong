# 任务完成状态可靠同步设计

## 目标

修复“用户已经勾选完成，但云端仍保留未完成状态，次日继续推送”的问题。修复只覆盖任务同步链路，不调整页面布局、日期、顺延规则、天气、AI、登录、重要日子、反馈或 PWA 的业务行为。

## 根因

任务勾选后，页面先修改本地数据，再异步写入 Supabase。写入失败时，本地仍显示完成，但任务没有进入可重试队列；同时账号区域仍显示“已同步”。重新打开或登录后，云端旧的未完成记录会覆盖本地完成记录，随后顺延和推送继续把它当作未完成任务。

## 设计

1. 每次新增、编辑、完成、删除、顺延或撤销顺延任务时，将该任务标记为 `syncPending: true`。
2. 只有对应版本成功写入 Supabase 后，才清除 `syncPending` 并记录 `syncedUserId`。
3. 登录、重新打开页面、网络恢复或页面重新可见时，自动重试待同步任务。
4. 读取云端任务时按 ID 合并：
   - 本地待同步任务优先；
   - 本地更新时间晚于云端时，将本地任务视为待同步并保留；
   - 其他情况采用云端记录；
   - 已在云端删除且本地没有待同步变更的任务不再保留。
5. 同一个任务的写入串行执行，并用更新时间校验写入版本，避免快速连续点击导致旧请求把新状态标成已同步。
6. 账号区域仅在不存在待同步任务时显示“已同步”；失败时明确显示等待同步。

## 数据与兼容性

`syncPending` 只保存在浏览器本地，不新增或修改 Supabase 字段。旧版本本地数据没有该字段时默认为 `false`；如果旧本地记录的 `updatedAt` 晚于云端 `updated_at`，合并过程会自动恢复成待同步状态。

## 验收标准

- 完成任务写入失败后，本地完成状态不会被云端旧状态覆盖。
- 网络恢复或重新打开页面后会自动补传。
- 补传成功后才显示“已同步”。
- 快速连续切换完成状态，最终云端状态与最后一次操作一致。
- 现有 UI 结构测试、AI 测试、PWA 资源和其他功能保持通过。
